# Technical Writing & Documentation | الكتابة التقنية والتوثيق

## Arabic Description | وصف بالعربية
قواعد صارمة لإنتاج توثيق تقني عالي الجودة يسهل فهمه واستخدامه من قبل المطورين والمستخدمين.

---

## Strict Rules | قواعد صارمة

### 1. Clarity & Conciseness
- **Plain English**: Use simple, direct language. Avoid unnecessary jargon.
- **Brevity**: Be as concise as possible while remaining complete. Use bullet points and lists.

### 2. Structure & Organization
- **Consistent Hierarchy**: Use proper heading levels (H1, H2, H3).
- **Navigation**: Include a Table of Contents for long documents.
- **Searchability**: Use keywords that users are likely to search for.

### 3. Visuals & Examples
- **Code Snippets**: All code examples MUST be correct, tested, and syntax-highlighted.
- **Diagrams**: Use diagrams (Mermaid, Draw.io) to explain complex architectures or flows.

### 4. Audience Alignment
- **Know Your Reader**: Tailor the technical depth based on whether the reader is a beginner, expert, or non-technical stakeholder.
- **User Personas**: Document for specific personas (e.g., "Developer Guide" vs. "API Reference").

### 5. Maintenance
- **Stay Updated**: Documentation MUST be updated as soon as the code or process changes.
- **Versioning**: If documenting an API or library, ensure the documentation version matches the code version.
